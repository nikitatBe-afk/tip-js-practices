## Организация кода

`task-service.js` отвечает за операции над моделью задач: создание, поиск, изменение статуса, удаление, переименование и редактирование задачи. Функции этого модуля не работают напрямую с DOM или `localStorage`.

`form-validation.js` содержит чистую функцию `validateTaskDraft`, которая проверяет значения, полученные из формы. Она преобразует и проверяет `id`, удаляет краевые пробелы из названия, проверяет приоритет и различает режимы создания и редактирования.

`task-storage.js` отвечает за проверку структуры сохранённых данных, чтение, запись и удаление данных из хранилища. Ошибки работы с хранилищем перехватываются внутри этого модуля.

`task-view.js` отвечает за создание и отображение элементов интерфейса: карточек задач, списка, сводки и пустого состояния. Названия задач выводятся через `textContent`.

`main.js` связывает все модули между собой. В нём хранится текущее состояние приложения, выбранный фильтр и `editingId`, обрабатываются события формы и кнопок, вызываются сервисные функции и выполняется сохранение данных.

Объект `storage` передаётся функциям хранения аргументом, чтобы модуль не был жёстко связан с глобальным `window.localStorage`. Это также позволяет проверять функции с помощью объекта-имитации.

Данные после `JSON.parse()` дополнительно проверяются, потому что корректный JSON ещё не гарантирует правильную структуру задач. Например, JSON может содержать число, неверные поля задачи или повторяющиеся `id`.

## Отладка и клавиатура

Для обязательной отладки необходимо установить точку останова внутри:

```js
handleFormSubmit
```

При корректном добавлении задачи необходимо зафиксировать:

```text
сырой draft: указать после выполнения отладки
результат validateTaskDraft: указать после выполнения отладки
результат addTask/updateTask: указать после выполнения отладки
JSON-строка перед записью: указать после выполнения отладки
```

Отдельно необходимо проверить сценарий повторного `id`, при котором `validateTaskDraft` возвращает ошибку, а сервисная операция и сохранение не выполняются.

Клавиатурная проверка:

- `Tab` используется для последовательного перехода между элементами формы и кнопками;
- `Enter` в форме должен вызывать `submit`;
- кнопки карточек доступны с клавиатуры;
- при переходе в режим редактирования фокус устанавливается на поле названия;
- после отмены редактирования форма возвращается в режим создания, а фокус устанавливается на поле `id`;
- после изменения статуса или удаления используется восстановление фокуса на соответствующее действие либо активный фильтр.

Фактическое прохождение клавиатурного сценария: **указать после ручной проверки**.

## Вывод

В практической работе была расширена логика приложения из ПР3. Добавлены создание и редактирование задач через одну форму, прикладная валидация, проверка уникальности `id`, нормализация названия, сохранение и восстановление состояния через `localStorage`, а также безопасная обработка повреждённых данных.

Была реализована функция `updateTask`, которая изменяет только название и приоритет выбранной задачи и сохраняет её исходный статус `completed`. Реализована чистая функция `validateTaskDraft`, которая не зависит от DOM и возвращает либо нормализованные данные, либо объект ошибок. Также создан модуль работы с хранилищем с проверкой полной схемы списка задач и обработкой исключений.

Нативная HTML-валидация используется для простых ограничений формы, например `required`, `min` и `maxlength`. Прикладная валидация проверяет правила самой модели: уникальность `id`, название после `trim()` и допустимый приоритет. После чтения данных из `localStorage` выполняется ещё один уровень проверки, потому что успешный `JSON.parse()` подтверждает только правильный синтаксис JSON, но не корректность структуры данных.

Проверки сервиса и новых модулей завершились успешно: **35 из 35** старых сценариев и **27 из 27** новых сценариев прошли без ошибок.
