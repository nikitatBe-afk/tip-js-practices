## Компоненты и состояние

Главным компонентом приложения является `App`.

В `App` находятся основные состояния:

- `tasks` — полный массив задач;
- `filters` — значения фильтров;
- `editingId` — идентификатор редактируемой задачи.

Компонент `TaskForm` хранит собственные состояния:

- `draft` — текущие значения полей формы;
- `errors` — ошибки проверки полей;
- `saveError` — сообщение об ошибке сохранения.

Приложение разделено на следующие компоненты:

- `App` — хранит общее состояние и связывает компоненты;
- `TaskStats` — отображает статистику;
- `TaskFilters` — отображает фильтры;
- `TaskForm` — отвечает за создание и редактирование задачи;
- `TaskList` — отображает список найденных задач;
- `TaskItem` — отображает отдельную задачу и кнопки действий.

Данные передаются от родительских компонентов к дочерним через `props`.

Например, `App` передаёт массив задач в `TaskList`, а `TaskList` передаёт отдельную задачу в `TaskItem`.

Действия передаются в обратном направлении через функции обратного вызова. Например, `TaskItem` вызывает `onToggle(task.id)`, после чего `App` изменяет общий массив задач.

Производные данные не хранятся в отдельных состояниях.

Видимый список вычисляется как:

```js
const visibleTasks = selectTasks(tasks, filters);
```

Статистика вычисляется как:

```js
const stats = getTaskStats(tasks);
```

Редактируемая задача находится по `editingId`.

Это позволяет избежать необходимости вручную синхронизировать несколько состояний.

Для перехода между созданием и редактированием используется ключ формы:

```jsx
key={editingId ?? 'new'}
```

При изменении ключа React создаёт состояние формы заново, поэтому данные предыдущей редактируемой задачи не переносятся в новую форму.

Изменения массивов и объектов выполняются без изменения исходных данных. Для этого используются `map`, `filter`, spread-оператор и создание новых объектов.

## Контрольные вопросы

### 1. Чем JSX отличается от строки HTML?

JSX — это синтаксис JavaScript для описания интерфейса. Он внешне похож на HTML, но обрабатывается JavaScript и React. В JSX можно вставлять выражения через `{}`.

### 2. Чем props отличаются от состояния?

`props` компонент получает от родителя и самостоятельно их не изменяет. Состояние принадлежит самому компоненту и может изменяться через функции обновления, например `setTasks`.

### 3. Почему изменение обычной переменной не заменяет `useState`?

Обычная локальная переменная не сохраняет значение между рендерами и её изменение не сообщает React о необходимости обновить интерфейс. `useState` хранит состояние между рендерами.

### 4. Когда требуется функциональная форма обновления состояния?

Когда новое состояние зависит от предыдущего.

Например:

```js
setTasks(previous => toggleTask(previous, id));
```

### 5. Почему нельзя менять объект задачи внутри поверхностной копии массива?

Потому что новый массив может всё ещё содержать ссылки на старые объекты. Изменение такого объекта изменит исходные данные. Поэтому при изменении задачи создаётся также новый объект.

### 6. Для чего списку стабильный `key` и почему индекс здесь не подходит?

`key` помогает React правильно определять элементы списка между рендерами. Индекс массива может измениться после удаления или изменения порядка элементов, поэтому используется стабильный `task.id`.

### 7. Почему видимая выборка и статистика не хранятся в отдельных состояниях?

Они уже могут быть вычислены из существующих `tasks` и `filters`. Если хранить их отдельно, пришлось бы постоянно синхронизировать несколько состояний.

### 8. Как дочерний компонент сообщает родителю о действии?

Через функцию обратного вызова, переданную через props.

Например:

```jsx
onToggle(task.id)
```

### 9. Что делает поле управляемым?

Значение поля берётся из состояния через `value`, а изменения записываются обратно через `onChange`.

### 10. Почему `categoryId` из `select` требует преобразования?

Значение HTML-поля `select` приходит строкой, а `categoryId` в модели задачи является числом.

### 11. Как меняется состояние формы при изменении её ключа?

React пересоздаёт компонент формы, поэтому её локальное состояние создаётся заново.

### 12. Почему подтверждение удаления не помещается внутрь функции обновления?

`window.confirm` является побочным действием. Функция обновления состояния должна оставаться чистой, особенно при использовании React `StrictMode`.

### 13. Как отличить отсутствие задач от отсутствия совпадений фильтра?

Полный массив `tasks` показывает, существуют ли задачи вообще, а `visibleTasks` показывает количество задач после применения фильтров.

### 14. Что проверяет `npm test` и чего он не проверяет?

`npm test` проверяет предметные функции из `task-service.js`: валидацию, фильтрацию, статистику и операции над задачами.

Эти тесты не запускают React-интерфейс и не проверяют правильность работы компонентов в браузере.

### 15. Какие части приложения потребуется изменить для подключения API в ПР8?

Операции создания, получения, изменения и удаления задач потребуется связать с HTTP-запросами к серверу. Синхронные операции будут заменены на асинхронные, а также потребуется обработка загрузки и ошибок API.
